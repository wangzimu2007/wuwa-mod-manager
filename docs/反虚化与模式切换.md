# 反虚化与模式切换：实测结论与排障

这份文档记录的是**实测出来的结论**，不是推测。每条都附了现象和判断依据，方便复现。

---

## 一、先搞清楚"虚化"有几种

讨论之前必须先区分三个完全不同的东西，社区里经常混为一谈：

| 现象 | 触发条件 | 由谁控制 |
|---|---|---|
| **A. 镜头贴近角色变透明**（抖动式淡出） | 相机贴到角色身上 | 游戏的角色材质不透明度通道 |
| **B. 和谐遮罩 / 光效** | 一直存在 | RabbitFX 的 `$censor` 之类 |
| **C. 相机穿模** | 靠得太近 | 模型碰撞体，工具改不了 |

本文说的"反虚化"专指 **A**。

---

## 二、四种方案实测对比

| 方案 | 形式 | 实测结果 |
|---|---|---|
| RabbitFX `$censor = 1` | Mod ini 变量 | ❌ 无效。它做的是解绑贴图（`ps-t50/t51 = null`），不是反淡出；副作用是可能丢贴图 |
| [WuwaTFR](https://github.com/)（ReShade 插件） | `EnableTFR=1` | ✅ **无 Mod 时有效**；有 RabbitFX 时失效 |
| Remove Transparency Filter / 去除透明效果MOD | WWMI Mod（按 shader hash 覆盖） | ⚠️ 与 RabbitFX 硬冲突：RabbitFX 先改写 shader，hash 对不上 |
| 自制材质贴图（改 R 通道） | Mod 资源 | 理论可行但每个角色单独做，未落地 |

### 为什么它们互相排斥

```text
游戏原始着色器
   ├─ RabbitFX 用 ShaderRegex 改写 → Mod 贴图/实体化生效
   │     └─ WuwaTFR 再看到时结构已变 → 匹配不上 → 失效
   └─ 按 hash 覆盖的方案（Prevent Transparency）
         └─ 同样撞 RabbitFX 改写后的 hash
```

所以现状是**按模式分工**：

| 模式 | Mod 外观 | 反虚化 | 光追 |
|---|---|---|---|
| Mod 模式 | ✅ | ❌ | ❌ |
| 光追模式 | ❌ 原版 | ✅ | ✅ |

例外：自带完整 RabbitFX 材质通道的皮肤（如部分付费精品）在 Mod 模式下也不淡出——那是作者做全了，不是工具的功劳。

---

## 三、切换模式"第一次不生效"的根因

**现象**：启动器切到光追模式 → 进游戏负载条没变红、光追没开 → 退出再启动一次才正常。Mod 模式反向同理。

**根因**：光追开关由**三个地方**共同决定，只写前两个不够。

| 位置 | 键 | 作用 |
|---|---|---|
| LocalStorage.db | `RayTracing`（0/3）、`RayTracedGI/Reflection/Shadow` | 游戏设置界面读写的值 |
| GameUserSettings.ini | `sg.RayTracingQuality`（0=关，3=高） | 画质档位 |
| **Engine.ini** | **`r.RayTracing.LoadConfig`（0/1）** | **引擎初始化时是否加载光追配置** |

实测时间戳（一次失败的光追切换）：

```text
02:12:16  游戏启动          ← 引擎此时读 Engine.ini，LoadConfig 还是上一种模式的 0
02:13:32  游戏才回写 LoadConfig=1   ← 晚了 76 秒
02:14:04  游戏再写 GameUserSettings
```

也就是说：**只写 DB 和 GameUserSettings，引擎初始化时读不到，这一局就不会开光追**；游戏运行中自己补写，下次启动才生效——这就是"必须重启一次"的来源。

**修法**：切换脚本在启动前把三处一起写，并在写完后回读校验（`sg.RayTracingQuality` 是 0/3 档位、`LoadConfig` 是 0/1，两者不能混比）。

---

## 四、另一个坑：进程没退干净

点 X 关游戏后，`Client-Win64-Shipping` 常常还要几十秒才真正退出（窗口没了但进程还在，占着 2 GB 以上内存）。

这期间点启动器切模式，脚本会认为"游戏还在运行"而拒绝执行，用户容易误判成"启动器坏了"或"弹了官方启动器"。

**修法**：启动器点卡片后先轮询进程，最多等 90 秒让它自然退出；超时才询问是否强制结束。

## 五、排障清单

| 现象 | 先查什么 |
|---|---|
| 提示 `Ray tracing is ON ... mods are off` | ① `Engine.ini` 的 `LoadConfig` ② `GameUserSettings.ini` 的 `sg.RayTracingQuality` ③ 游戏内设置界面是否显示"需重启" |
| 反虚化无效 | ① 当前是不是有 RabbitFX（Mod 模式）② `EnableTFR` 是否为 1 ③ 改完有没有重启游戏 |
| 切换脚本被拒绝 | 进程列表里是否还有 `Client-Win64-Shipping` / `Wuthering Waves` |
| 角色贴图异常 | 是否同时启用了两套互相覆盖 shader 的 Mod |

## 六、关于"改材质贴图"这条路（未落地）

3.x 版角色材质贴图的通道大致是：`R=不透明度`、`G=金属度`、`B=战损`、`A=遮罩`。

思路上可以给 Mod 附带一张自己的材质图（`Resource\RabbitFX\Materialmap`），把 R 通道拉满，让角色始终不透明。它比着色器补丁稳（游戏更新不易失效），但成本是：

- 每个角色要单独抓贴图、改通道
- 原贴图来自游戏本体，**不能分发**
- 素材不同（部分皮肤自带改过的材质）要单独适配

所以本仓库没有实现它，只记录思路。
