# 鸣潮启动器 · 卡等待/未响应 排查记录

> 日期：2026-11-24
> 现象：双击启动器、点模式后卡在「等待游戏退出… 14 秒」，但游戏根本没开
> 结论：**系统里有别的 `launcher.exe`，被按进程名误判成游戏进程**

---

## 一、现象与误判链

```text
用户操作：今天第一次点启动器 → 选 Mod 模式
表现：底部出现「等待游戏退出… 14 秒」并一直涨
实际：游戏没启动过，任务管理器里也看不到鸣潮

原因：
  启动器里 Get-LingeringGame 按「进程名」匹配：
      Client-Win64-Shipping / Wuthering Waves / launcher
  而系统里当时存在 6 个 launcher.exe：
      pid 55248（父） + 5 个子进程，同一秒启动，父进程已退出成孤儿
      （路径读不到，明显不是鸣潮的启动器）
  → 被当成"游戏还没退干净" → 进入 90 秒等待循环
```

---

## 二、修复

```text
文件：E:\GameMods\WWMI-Mods\工具\鸣潮启动器.ps1
函数：Get-LingeringGame

旧：
  @(Get-Process -Name 'Client-Win64-Shipping', 'Wuthering Waves', 'launcher')

新：
  · Client-Win64-Shipping / Wuthering Waves → 直接算游戏进程
  · launcher.exe → 必须路径包含 "Wuthering Waves" 或 "鸣潮" 才算
  · 路径读不到（受保护进程）→ 忽略，不参与判断

备份：鸣潮启动器.ps1.bak-proc
```

验证：

```text
修复后同样环境下匹配到 0 个进程
启动器启动、窗口响应正常，点模式不再等待
```

## 三、同一启动器的历史问题（一起记录）

### 1. 窗口「未响应」（2026-11-21 修）

```text
原因：检测到游戏残留进程后，在界面线程里 Start-Sleep 轮询，最多 90 秒
      → 窗口不处理消息，被 Windows 判定「未响应」

修复：新增 Wait-UI 函数（DispatcherFrame + DispatcherTimer），
      等待期间保持界面刷新
备份：鸣潮启动器.ps1.bak-pump
```

### 2. 今天这次（2026-11-24）

```text
原因：进程名误判（见上）
修复：按路径识别
```

## 四、教训

1. **按进程名匹配系统进程不可靠**：`launcher.exe`、`launcher` 这类通用名字在系统里可能有一堆，必须叠加路径或签名判断。
2. 读不到路径的进程，应该**当作未知忽略**，而不是当作目标。
3. 界面线程里做长时间等待必须用消息泵（DispatcherFrame），否则一律「未响应」。
4. 排查这类问题时先看 `Get-Process | Where 名字匹配` 的真实列表，再决定匹配规则。

## 五、快速自检命令

```powershell
# 看有没有会触发误判的进程
Get-Process -Name 'Client-Win64-Shipping','Wuthering Waves','launcher' -ErrorAction SilentlyContinue |
  Select-Object ProcessName, Id, Path

# 看当前会不会被判定为"游戏未退出"（修复后的逻辑）
$hit = @()
$hit += @(Get-Process -Name 'Client-Win64-Shipping','Wuthering Waves' -ErrorAction SilentlyContinue)
foreach ($p in @(Get-Process -Name 'launcher' -ErrorAction SilentlyContinue)) {
    if (-not $p) { continue }
    $path = ''
    try { $path = $p.Path } catch { }
    if (-not $path) { try { $path = $p.MainModule.FileName } catch { } }
    if ($path -and $path -match '(?i)Wuthering Waves|鸣潮') { $hit += $p }
}
"命中 $($hit.Count) 个"
```
